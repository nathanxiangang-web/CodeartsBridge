# V1.2 超时白跑：根因诊断与修复方案

> 目标：根治 Worker 任务「30 分钟硬超时白跑、零产出」问题，为 v1.2 生产化关键路径（P1–P10）扫清障碍。

## 一、诊断结论（单一主导根因）

CodeArts CLI 当前读取的权限存储为：

```
C:\Users\Nathan\.codeartsdoer\codearts-data\storage\permission\global.json
```

其中 `edit`、`write`、`external_directory_write`、`dotfile` 四类权限的 `action` 均为 `ask`：

```json
{ "permission": "edit",                   "pattern": "*", "action": "ask" },
{ "permission": "write",                  "pattern": "*", "action": "ask" },
{ "permission": "external_directory_write","pattern": "*", "action": "ask" },
{ "permission": "dotfile",                "pattern": "*", "action": "ask" }
```

而 `bash` 命令由 `permission/config.json` 的 `bash_mode = always_allow`（且 bridge 额外传 `--auto`）放行。

**后果**：Worker 在无人值守的 JSON 模式下，任何 `edit`/`write`/写 outbox/写临时目录/写点文件 的操作都会被 CLI 走 `ask` 流程，无人应答即 `auto-reject`。Worker 因此无法编辑任何文件、无法交付，只能反复空转重试，最终耗尽 30 分钟硬超时（1800s），token 大量白烧。

## 二、证据链

### 2.1 权限拒绝统计（全部 attempt 的 stderr 汇总）

| 权限类型 | 次数 | 含义 |
|---|---|---|
| `edit` | 85 | 核心文件编辑被拒 |

! permission requested: dotfile (.opencode\run-tests.ps1); auto-rejecting

### 2.2 两份 global.json 的路径混淆

| 路径 | 状态 | action |
|---|---|---|
| `codearts-data\storage\permission\global.json` | **当前 CLI 实际读取**（`codearts debug paths` 的 data 目录） | edit/write 等 = **ask** |
| `cli-data\storage\permission\global.json` | 已废弃（非 CLI data 目录） | edit/write 等 = allow |

结论：2026-09-07 的一次「修复」把 `allow` 写进了错误的 `cli-data` 路径，未生效；真正生效的 `codearts-data` 路径仍停留在 `ask`。

## 三、三层根因

1. **权限层（致命）**：`edit`/`write`/`external_directory_write`/`dotfile` = `ask`，非交互即 auto-reject。Worker 无法写代码、无法交付。
2. **环境层（放大）**：edit 被拒后 Worker 退化为用 bash（`powershell -NoProfile -Command`）手写文件，遭遇 `$` 剥离、引号/here-string 解析失败（`[char]36`、DOLLAR 占位、base64 等 hack），token 与时间爆炸。
3. **调度层（兜底失效）**：硬超时 30 分钟（规范应 10–15）；`Invoke-SshWorker` 未传递 `SoftTimeoutSeconds`；WORKER.md 规则 11「两次失败即交检查点」未被 Worker 遵守，任务空跑到硬超时才 FAILED。

## 四、修复方案

### 步骤 1（根治）：修正 CLI 权限配置

将 `codearts-data\storage\permission\global.json` 中以下权限的 `action` 从 `ask` 改为 `allow`：

- `edit`、`write`、`external_directory_write`、`dotfile`
- 视需要同步放开 `browser`、`webfetch`（当前 remote guardrail 已禁网络，风险可控）

保留 `bash_mode = always_allow`；`external_directory_read`、`websearch` 已是 allow。

### 步骤 2（防混淆）：清理废弃配置

删除或同步 `cli-data\storage\permission\global.json`，避免未来再次改错路径。

### 步骤 3（兜底加固）：bridge.ps1

1. `Invoke-SshWorker`（`scripts/bridge.ps1:1351`）补充 `SoftTimeoutSeconds` 参数并透传，与 local / ssh-shell 对齐。
2. 短任务硬超时统一降到 15 分钟（`docs/v1.2-production-plan.md` 已声明 15 分钟硬限）。
3. `doctor` 增加权限自检：读取当前 CLI 的 `codearts-data\storage\permission\global.json`，若 edit/write/external_directory_write/dotfile 非 allow 则告警，避免静默白跑。

### 步骤 4（协议加固，可选）：WORKER.md

强化规则 11：连续两次 `auto-reject` / 编辑 / 命令构造失败即写 `CHECKPOINT.md` + `ASSISTANCE_REQUEST.md`，禁止继续消耗到硬超时。

## 五、验证方法

1. 用最小 prompt 跑 `codearts run --auto` 冒烟：确认 edit/write 不再触发 `auto-reject`（可从 stderr 无 `permission requested` 判定）。
2. `doctor` 权限自检通过。
3. 重跑此前白跑的短任务（P1 bootstrap 最小单元、P2 policy-runtime、P3 daemon-proof），硬超时 15 分钟，确认不再空转。

## 六、对 v1.2 关键路径的解锁

P1–P3（当前停点）全部因该权限问题停滞。修复后：

- P1（W01 remote-bootstrap）、P2（W02 policy-runtime）由 Architect 抢救验证 —— 已局部改动能正常前进。
- P3（W03 Windows inherited-pipe proof）在 Windows 真机重跑，重点解决 `ping` 方案让 daemon 卡 30 秒的问题（需另做父进程快速退出 + 子进程继承管道的 precheck）。
- P4–P7 Worker 短任务、P8–P10 集成/联调/发布门随之可逐项推进。
