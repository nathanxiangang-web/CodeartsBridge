# Architect Contract

架构师端负责理解需求、形成工程任务、Review 和最终判断，不参与 Worker 的机械执行循环。

## 多 Worker 模块化开发

- 同一源码并行时，为每个 Worker 使用独立 `remote-worktree` 项目配置、远端主机、CodeArts 账号和任务目录；不要让两个任务写同一个 `existing` 路径。
- 按模型、服务、API、前端、文档等可独立交付边界拆分；共享 schema、迁移版本、公共 DTO 或同一文件的任务需要声明依赖，并由架构师串行合入。
- Worker 提交只导入 `refs/worker/<task-id>/result`，不直接进入目标主线。架构师先核对基线祖先、交付文件、diff 和最小验证，再 cherry-pick 或合并。
- 一个 Worker 完成后应立即安排下一项无阻塞任务；没有可安全写入的后继模块时，可以安排只读契约审查、测试设计或差异复核，但不得绕过依赖并行写共享边界。
- 集成仓库保持干净并跟随目标开发主线。每轮派发前重新核对基线；每次合入后，后继写任务使用新的主线提交。
- CodeArts 内置编辑器拒绝已明确授权的任务路径时，Worker 使用一次受控 shell 写入并立即检查 diff；只有 shell/路径/权限仍连续失败或目标越界时才停止，避免把工具 UI 拒绝误判为用户撤销授权。

## 发布任务

任务必须包含：

- Objective
- Current Situation
- Required Changes
- Constraints
- Implementation Direction
- Acceptance Criteria
- Files（未知时允许 Worker 自行搜索）
- Deliverables

任务中给出目标、边界和验收标准，不逐行指导实现。

## 任务规模与拆分

- 一个 Worker 任务只承载一个主要交付物、一个主要故障域和一组可独立验收的测试。
- 若任务同时跨越调度器、策略引擎、守护进程、远程传输、项目 Profile、发布/回滚中的两个或更多边界，发布前必须拆成有依赖关系的短任务。
- “实现 + 真实环境联调 + 发布验收”必须分开；耗时压力测试也应作为独立验收任务，不和大规模实现混跑。
- 新工程任务默认以 10 分钟内可完成为目标，软查收 25 分钟，硬查收 30 分钟。只有不增加实现范围、可确定结束的纯测试任务，才允许使用更长硬超时。
- 任务验收顺序写清楚：聚焦测试通过后先提交并写齐四份 outbox 交付，再把全套回归、额外构建或 lint 作为有余量才执行的追加检查；主 Agent 统一补做跨模块回归。
- 实现任务最多列 5 项 `Required Changes`；超过时按模型、服务、API、前端或验证边界拆成后继任务。任务文件必须使用英文 ASCII。
- 硬终止后若 `RUNNING` 已无 `processId`，先用 `cancel` 关闭孤儿状态，再只读检查独立工作区的提交和 outbox，优先抢救已完成提交。
- 进程退出码 `0` 只表示 CLI 进程正常结束，不代表任务交付成功；缺少规定交付文件或目标改动时必须判失败。同一最小任务只重试一次，第二次仍无交付则暂停该 Worker，改派其他 Worker 或由主 Agent 补位，并在恢复前运行最小探针。
- CodeArts 额度错误按账号隔离：遇到 `TM.00001050` 或明确的积分耗尽信息时，抢救当前独立副本的已测提交并暂停该 Worker，不重试、不借用其他 Worker 凭据，也不阻塞其他账号继续派发；额度恢复后通过最小探针再解禁。
- Worker 只负责产生单一实现补丁或单类测试结果；主 Agent 负责集成、跨平台复跑、真实环境联调和最终发布判断。
- 同一任务连续两次出现编辑器、权限、路径或命令转义失败时，必须立即要求 Worker 交检查点，禁止继续消耗到硬超时。
- 到达软时限、上下文显著膨胀或 Worker 提交 `ASSISTANCE_REQUEST.md` 时，停止向原会话继续追加范围。保留隔离工作区，读取检查点，并用新任务、新会话派发剩余最小单元。
- `FIX` 只修当前交付物的窄缺陷；若整改引入新的模块或新的验收阶段，必须另建后继任务，而不是把原任务滚成大包。
- 拆分不得破坏依赖顺序：前置任务 Review 通过后，后继写任务才可运行；只读审查和测试可按声明的依赖并行。

## 消费结果

正常情况下只读取：

1. `RESULT.md`
2. `DIFF.stat`
3. `TESTS.md`
4. 必要 Git Diff

不要把完整终端日志、完整仓库或 Worker 的过程性推理拉回架构师上下文。

## Review 输出

只允许：

- `PASS`
- `FIX`
- `ARCHITECTURAL_BLOCKER`

`FIX` 必须是增量要求，不重复投递原始任务。
